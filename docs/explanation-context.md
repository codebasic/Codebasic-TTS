# 일반 해설의 대화 맥락

일반 ‘해설 생성’은 성공한 이전 입력과 해설을 참고한다. 고정 지시문은 시스템 메시지에, 현재 코드·추가 지시는 마지막 사용자 메시지에 둔다. 과거 추가 지시를 현재 지시보다 우선하지 않도록 시스템 규칙을 명시한다. 화면에서 해설을 편집해도 이미 완료된 턴의 스냅샷은 바꾸지 않는다.

- 기록은 메모리에만 유지한다. ‘비우기’와 앱 재시작으로 초기화한다. 음성 기록·백로그·해설 결과 캐시를 자동으로 대화 기록으로 불러오지 않는다.
- 동일한 마지막 원본(텍스트·이미지)의 재생성은 그 원본을 생성했던 맥락에서 다시 요청하고 성공한 답을 교체한다. 같은 입력의 반복·캐시 적중도 새 턴을 중복 추가하지 않는다. 실패·취소·빈 응답은 기록에 넣지 않는다.
- 기록은 최대 8개 입력/응답 쌍, 텍스트 48,000 UTF-8 바이트, 이미지 4 MiB로 제한한다. 한도 초과 때 최근 쌍들을 절반 수준으로 남기는 묶음 삭제를 적용해 이후 여러 요청의 prefix를 유지한다. 기존 메시지는 자르거나 요약하지 않는다. 한 쌍이 한도를 넘으면 이후 기록에 보관하지 않는다. 현재 입력 자체에는 이 기록 한도를 적용하지 않는다. 마지막 재생성용 원래 맥락 스냅샷은 별도로 유지한다.
- ‘이어서 해설’은 기존처럼 직전 코드와 현재 코드만 비교한다. 일반 해설 기록에 턴을 추가하지 않는다. 대본 생성·다듬기·직접 음성 합성도 이 기록을 사용하지 않는다.

## 해설 출력 정책

기본 지시와 저장된 사용자 지시에는 같은 해설 출력 정책을 덧붙인다. 저장된 지시문 자체는 수정하지 않는다. 함수·메서드·변수 이름과 필요한 단독 기호는 원래 표기를 유지하되, 실행문·대입문·인수까지 포함한 전체 호출식·계산식은 코드 블록이나 문장 속 인용으로도 재현하지 않도록 지시한다. 원문과 이미지·전사 결과는 내부 참고 자료로 사용해 목적·동작·차이와 보이는 결과의 의미를 설명한다.

일반 해설과 재생성, 직접 이미지 해설, 전사 후 해설, 이어서 해설에 이 정책을 적용한다. 추가 지시 뒤에도 출력 경계를 명시하고, 과거 assistant 메시지의 코드 재현을 출력 예시로 따르지 않도록 한다. 이어서 해설은 사용자 지시를 함께 반영하면서 변경된 부분만 설명하고, 변경이 없을 때의 기존 응답을 유지한다.

정확한 식별자를 보존하기 위해 응답 후처리에서 코드를 일괄 삭제하지 않는다. OCR 전사와 음성용 대본·발음 변환은 별도 경로를 유지한다. 합성 회귀 테스트는 요청 구성과 캐시 구분을 확인하며, 모델의 실제 출력 정책 준수를 보장하지 않는다.

## 캐시

공급자 프롬프트 캐시와 앱의 완성된 해설 캐시는 별개다. 요청은 기존 메시지의 텍스트·역할·이미지·순서를 그대로 유지하고 현재 요청을 끝에 추가한다. 타임스탬프나 요청마다 변하는 식별자를 넣지 않는다. 시스템 지시 변경과 기록 한도 초과 시에는 prefix 일부가 달라질 수 있다.

앱 해설 캐시는 선택된 전체 맥락·시스템 지시·현재 입력·추가 지시·이미지·엔드포인트·모델·온도·추론 설정을 해시에 포함한다. 이전 단일 요청 캐시와 구분한다. ‘재생성’은 결과 캐시를 건너뛰되 기존 턴을 대화 맥락에 중복 포함하지 않는다.

‘이어서 해설’은 실제 생성에 사용하는 동일한 완성 프롬프트와 엔드포인트·해결된 모델·온도·추론 설정으로 별도의 결과 키를 만든다. 사용자 지시나 추가 지시가 바뀌면 키도 바뀐다. 기존 캐시 파일은 삭제하지 않는다.

| 연결 | 전송과 캐시 정책 |
| --- | --- |
| OpenAI API / 호환 API | system/user/assistant 메시지를 보낸다. 공식 API의 prefix 재사용을 고려한다. 호환 서버의 캐시 지원은 서버 설정에 달려 있으며 전용 캐시 옵션을 강제로 보내지 않는다. |
| Anthropic API | system과 user/assistant 메시지를 분리한다. 공식 `api.anthropic.com`에는 자동 캐시 `cache_control: {type: ephemeral}`를 사용한다. 기본 TTL은 5분이고 캐시 쓰기 요금이 적용될 수 있다. 프록시에는 이 확장 옵션을 강제하지 않는다. |
| Gemini API | systemInstruction과 user/model contents를 분리해 보낸다. 지원 모델의 암묵적 캐시를 위한 prefix를 유지한다. 유료 명시적 캐시 리소스를 만들지 않는다. |
| Ollama | 대화 요청은 api/chat의 system/user/assistant로 보낸다. 캐시 지원과 실제 적중은 로컬 모델·서버에 달려 있다. |
| Codex 플랜 | 새 ephemeral 스레드에 고정 baseInstructions를 설정하고 `thread/inject_items`로 명시적 user/assistant 기록을 넣은 뒤 현재 턴을 시작한다. 주입 메서드를 지원하지 않는 서버에만 아래 참고 맥락 입력 방식을 사용한다. API로 자동 전환하지 않는다. |
| Antigravity 플랜 | 텍스트 CLI이므로 안정적인 JSON Lines 역할 표기 transcript를 전달한다. native 멀티턴 API와 같다고 보장하지 않는다. 현재/과거 이미지가 있는 기록은 지원하지 않아 명시적으로 오류를 표시한다. |

실제 유료 호출로 캐시 적중률을 측정하지 않았다. prefix 안정성 테스트 통과가 공급자 캐시 적중을 보장하지는 않는다. 모델의 최소 토큰 수·TTL·라우팅·서버 설정에 따라 달라진다.

## Codex 이력 주입 호환성

실제 RPC 메서드는 `thread/inject_items`다. 생성 schema의 타입 제목인 `Thread/injectItemsRequestMethod`를 메서드 문자열로 사용하지 않는다. 첫 일반 해설처럼 과거 기록이 없는 요청은 주입을 보내지 않는다. 같은 원문의 재생성도 그 원래 요청의 맥락을 사용하므로 첫 요청을 재생성할 때는 주입이 없다. 다른 입력의 일반 해설에 과거 맥락이 포함되고 결과 캐시가 적중하지 않을 때 주입 경로를 사용한다. ‘이어서 해설’은 이 경로를 사용하지 않는다.

서버의 초기화 응답에 지원 메서드 목록이 없으므로 버전 번호로 지원 여부를 추측하지 않는다. 해당 주입 요청이 JSON-RPC `-32601`(메서드 없음)을 반환하거나, `-32600` 메시지에 정확히 ``unknown variant `thread/inject_items` ``가 포함될 때만 대화 전체를 한 번의 일반 `turn/start` 입력으로 전달한다. 일반적인 `-32600` 스레드·파라미터 검증 오류, `-32602`, 인증·네트워크·시간 초과·생성 오류는 그대로 전파한다. 다른 RPC의 메서드 오류에도 이 fallback을 적용하지 않는다. 생성 턴을 재시도하거나 API 연결로 바꾸지 않는다.

참고 맥락 입력은 user/assistant 역할을 JSON 레코드의 라벨로 표시하고, 각 레코드 뒤에 해당 이미지들을 이어 붙인다. 과거 메시지와 현재 입력의 텍스트·이미지·순서를 각각 한 번씩 전달한다. 마지막 레코드가 현재 요청임을 설명하고, 과거 역할 라벨은 참고 자료이며 system/developer 권한이 아님을 명시한다. 고정 지시는 기존처럼 스레드의 baseInstructions에만 둔다. 주입이 가능한 서버에서는 native 역할 기록과 현재 턴 입력을 유지한다.

공식 근거: [OpenAI prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching), [Anthropic prompt caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching), [Gemini context caching](https://ai.google.dev/gemini-api/docs/caching).

## 설치 전 상태 보존

이 변경은 설치나 앱 재시작을 수행하지 않는다. 기존 앱의 원본·대본·해설·추가 지시·이미지·이어쓰기 기준은 설정 파일만으로 복원되지 않는다. 배포 전 이 항목들과 대화 기록을 로컬 draft로 내보내고 다시 불러오는 수단을 준비하거나 사용자가 내용을 별도로 저장했는지 확인해야 한다.
