# 외부 에이전트 대본 받기

앱의 **에이전트** 탭에서 기본 지시 또는 여러 사용자 지시를 선택합니다. **새 지시…**에서 이름과 본문을 로컬에 저장합니다. 저장한 지시는 이름으로 찾을 수 있고, 본문 전체를 확인하거나 복사할 수 있습니다. 연결을 허용한 세션에 직접 고른 저장본을 공유합니다.

**공유 지시 선택**에는 현재 공유 대상으로 고른 지시가 표시됩니다. 새 지시를 저장하면 편집기에 열리며, 공유하려면 목록에서 직접 선택하세요. 검색하거나 목록을 열기만 해서는 공유되지 않습니다. **저장**하기 전의 변경은 외부에 공유되지 않으며, 다른 지시를 보고 돌아와도 유지됩니다. **되돌리기**는 마지막 저장본을 다시 표시합니다. 저장한 새 버전을 공유하려면 해당 지시를 다시 선택하세요. 기본 지시의 에이전트용 수정은 앱 내 직접 생성이나 호환용 MCP 지시에 영향을 주지 않습니다.

## 서명된 로컬 도우미 (선택)

도우미 없이도 대본을 붙여넣고 편집할 수 있습니다. 지시를 선택한 경우, 연결된 도우미가 **실제로 조회한 지시의 정확한 버전**을 증명해야 대본을 받을 수 있습니다.

1. 앱에 포함된 **CodebasicAgentMCP**를 stdio 실행 명령으로 등록합니다. 보낼 데이터는 텍스트이며, 호스트 명령 외에 인자·환경 변수·별도 인증 정보가 필요하지 않습니다.
2. 에이전트가 `tts_agent_status`를 호출하면 **에이전트 연결**에 승인 요청이 표시됩니다. 해당 행의 **허용**을 누릅니다. 이미 승인한 다른 앱은 계속 받을 수 있습니다. 각 연결에서 따로 받기를 멈추거나 다시 켜고, 기억한 앱의 승인을 철회할 수 있습니다. **전체 받기 끄기**는 모든 연결의 수신과 지시 공유를 멈춥니다.
3. 지시를 선택하지 않으면 각 승인된 연결에서 일반 대본을 보낼 수 있습니다. 저장 지시를 공유할 때는 받을 앱을 지정합니다. 해당 앱은 선택한 정확한 버전을 읽고 그 버전의 증명이 담긴 대본을 제출합니다. 지시를 편집하거나 삭제하거나 선택을 풀면 기존 증명은 폐기됩니다.
4. 새로 받은 대본은 편집기에 즉시 열립니다. 이미 있던 대본은 수정 여부에 관계없이 편집기 옆 **대본 목록**에 남습니다. 목록은 최신이 위이고, 제목으로 검색하거나 접을 수 있습니다. 목록에서 제목을 검색하는 동안 도착한 대본은 보던 글을 바꾸지 않고 목록에만 추가됩니다. 접기·검색·새 도착은 어떤 대본도 닫거나 지우지 않습니다. 수정했을 때만 보이는 **받은 원문으로 되돌리기**로 해당 문서의 받은 버전을 복원할 수 있습니다. 재생은 사용자가 직접 눌러야 시작됩니다.

```toml
[mcp_servers.codebasic_tts_agent]
command = "/absolute/path/to/Codebasic TTS.app/Contents/Helpers/CodebasicAgentMCP"
```

앱의 **MCP 설정 복사** 메뉴로 현재 번들 경로가 포함된 Codex 설정이나 Claude Code 사용자 범위 등록 명령을 복사할 수 있습니다. 복사만으로 설정 파일을 바꾸거나 명령을 실행하지 않습니다. 다른 stdio MCP 클라이언트에도 같은 절대 경로를 실행 명령으로 지정하면 됩니다. 앱을 옮기거나 이름을 바꾸면 이 명령 경로만 수정하세요. 전역 에이전트 설정은 앱이 변경하지 않습니다.

- `tts_agent_status`: 앱 연결과 두 권한의 상태를 확인합니다. 지시나 대본은 읽지 않습니다.
- `get_tts_submission_guide`: 제출 형식을 돌려주는 읽기 전용 도구입니다. 어느 도구를 언제 쓰는지, 각 필드의 뜻과 한도, 예시, 결과 코드별 대처를 담습니다. 앱이 꺼져 있거나 허용 전이어도 읽을 수 있고, 지시·대본·승인 정보는 담지 않으며 아무 상태도 바꾸지 않습니다. 도구 스키마와 이 안내는 도우미 안의 한 필드 정의에서 만들어집니다.
- `submit_tts_draft`: 지시를 선택하지 않은 상태에서 `display_text`, 선택적인 `speech_text`와 `title`, `idempotency_key`를 보냅니다. 지시 선택이 활성 또는 만료·변경 대기 중이면 `instruction_required`로 거절되며 자동으로 우회하지 않습니다.
- `get_tts_instructions`: 인자 없이 호출하면 앱이 승인한 선택을 읽습니다. 정확한 `profile` ID를 지정하는 기존 호출도 지원합니다. 기존 기본 ID는 `explain`, `continue`, `normalize`입니다. 답변의 `revision`과 `body_sha256`은 정확한 버전과 UTF-8 원문을 식별합니다. 수신 증명은 도우미 내부에서만 관리됩니다.
- `submit_explanation_draft`: 읽은 `profile`과 `revision`, `display_text`, 선택적인 `speech_text`, `idempotency_key`를 보냅니다. 두 제출 도구 모두 같은 도우미 세션에서 같은 키와 내용으로 재시도하면 한 번만 열립니다. 같은 키를 다른 내용에 쓰면 거절되며, 같은 내용으로 새 문서를 열려면 새 키를 쓰세요. 접수된 대본의 재생은 사용자가 시작합니다.
- 호환용 기존 기본 지시 조회와 `speak_text`는 각각 그대로입니다. 증명 없는 이전 `mcp_tts_draft.py`는 자동 수신하지 않으며 붙여넣기를 안내합니다. 각 권한은 별개입니다.
- `title`은 대본 목록과 편집기 머리에만 보이는 이름입니다. 본문·복사·자막·합성·재생에는 들어가지 않고, **화면 글 그대로 읽기**도 본문만 읽습니다. 한 줄, 120자와 UTF-8 512바이트까지이며 넘으면 줄이지 않고 `too_large`로 거절합니다. 없거나 공백뿐이면 본문에서 공백이 아닌 첫 줄을 목록 이름으로 씁니다.
- 지시·화면 글·음성 대본은 각각 UTF-8 8 KiB(8192바이트)이고, 한 요청 프레임은 100 KiB입니다. 한도를 넘는 글은 자르지 않고 `too_large`로 거절하며 응답에 넘은 필드와 바이트 수를 담습니다. `tts_agent_status`의 `limits`에서 두 한도를 읽을 수 있습니다. 대본 수에는 한도가 없습니다. 받은 대본과 직접 쓴 글은 앱 데이터 폴더의 `drafts.sqlite`(0600)에 저장되어 앱을 다시 실행해도 목록·수정본·받은 원문이 그대로 돌아옵니다. 저장에 실패하면 새 수신만 `busy`로 거절하고 기존 글은 건드리지 않습니다. 모든 거절 응답은 `structuredContent.status`에 사유 코드를 담고, 앱의 연결 영역에도 사유가 표시됩니다. 새 대본은 분당 6개, 시간당 60개까지 받습니다. 두 한도 모두 시간이 지나면 풀리며, 받기를 직접 껐다 켜면 새로 셉니다. 같은 전송 키에 제목·본문·음성 대본이 모두 같으면 `duplicate`, 하나라도 다르면 `conflict`이며 기존 대본은 바뀌지 않습니다. 저장된 대본이 목록에 있는 동안에는 앱을 다시 실행해도 같은 답을 합니다. 목록에서 닫은 대본의 키는 에이전트마다 최근 128개까지, 앱이 실행 중인 동안만 기억합니다. 기존의 한도 초과 원문은 자르지 않으며 공유되지 않습니다.
- 열린 대본, 수신 증명, 도우미 승인 기록은 앱을 종료하면 사라집니다. 재생 후에는 기존 설정에 따라 음성 캐시·기록에 남을 수 있습니다.
- 앱이 비정상 종료되면 앱 재시작 및 다음 승인 시 이 버전이 만든 것으로 확인되고 더 이상 연결되지 않는 소켓에 한해 자동으로 복구합니다. “기존 소켓의 출처를 확인할 수 없어 그대로 두었습니다”가 보이면, 이전 **Codebasic TTS** 앱을 종료하고 새 앱에서 같은 동작을 다시 시도하세요. 계속 막히면 복사·붙여넣기를 사용하세요. 관리자가 정확한 경로가 종료된 이전 앱의 소켓임을 별도로 확인한 경우에만 그 항목을 다른 곳으로 옮길 수 있습니다. 경로 전체나 출처를 모르는 파일은 삭제하지 마세요.

## 연결 유지

**승인은 에이전트 앱 단위입니다.** 도우미를 직접 실행한 앱을 코드 서명으로 식별합니다. 식별자는 서명 팀 ID(없으면 서명 인증서)와 코드 서명 식별자(번들 ID)의 조합이며, 앱 이름·경로·PID는 쓰지 않습니다. 유효한 인증서로 강화 런타임 서명이 되어 있고 macOS 기본 구성요소(셸·시스템 인터프리터)가 아닌 앱이면, 한 번 승인한 뒤 그 앱이나 Codebasic TTS를 재시작·업데이트해도, 오래 쓰지 않아도 다시 승인하지 않습니다. 앱이 따로 등록할 것은 없습니다. 애드혹 서명이거나 서명이 없는 실행 파일, 셸(`/bin/zsh -c …`)이나 시스템 인터프리터를 거쳐 도우미를 실행하는 호스트는 앱을 구별할 수 없어 실행별로 승인합니다. 같은 서명된 런타임(예: 공용 `node`)으로 직접 실행되는 서로 다른 도구는 같은 앱으로 보입니다.

식별된 앱은 앱별 키로 새 챌린지에 응답합니다. 키는 `~/Library/Application Support/Codebasic TTS/agent-client-keys/`(폴더 0700, 파일 0600)에 저장됩니다. 키체인에 두면 자체 서명 빌드에서 앱을 다시 빌드·업데이트할 때마다 도우미가 키에 접근하지 못하기 때문입니다. Codebasic TTS는 실행 중인 상대 도우미와 호스트의 서명, 승인된 키를 확인합니다. 전체 받기와 해당 앱의 받기가 켜져 있을 때 다시 연결되고, 화면 잠금 중에는 모든 수신이 막힙니다. **잊기**를 누르면 해당 앱에 한해 진행 중인 요청과 기존 키를 거절합니다. 해당 호스트가 다시 등록하려면 해당 호스트가 직접 도우미를 `--forget-key` 인자로 실행해 자격증명을 폐기한 뒤 새 연결을 승인해야 합니다.

전송 키는 승인된 연결마다 따로 해석합니다. 등록된 앱에서 저장 문서가 남아 있으면 재시작 후에도 동일 키와 동일 제목·본문·낭독본은 중복으로 보고합니다. 임시 승인 세션을 다시 실행한 경우에는 재전송하기 전에 수신 목록을 확인하세요. 선택 지시는 사용자가 지정한 앱에만 공유하며 Codebasic TTS를 다시 실행하면 선택이 풀립니다.

## 긴 대본 보내기

터미널(PTY)을 거쳐 도우미에 쓰면 긴 줄이 잘리고 응답이 오지 않습니다. 파이프로 연결하고, 요청 하나를 UTF-8 JSON 한 줄로 끝까지 써야 합니다. `Helpers/tts_mcp_client.py`가 그렇게 보내며, 보낸 결과를 셋 중 하나로 알려 줍니다.

- `confirmed`: 앱이 이 요청에 `accepted` 또는 `duplicate`로 답했습니다.
- `rejected`: 앱·도우미·클라이언트가 거절했고 문서는 열리지 않았습니다.
- `unconfirmed`: 맞는 응답이 오지 않았습니다. 받았는지 알 수 없습니다.

`unconfirmed`는 자동으로 다시 보내지 않습니다. 같은 연결에서 같은 키와 같은 글, 새 요청 ID로 한 번만 다시 보내면 이미 받은 경우 `duplicate`가 옵니다. 출력에는 상태와 바이트 수만 있고 대본 글은 없습니다.

```sh
Helpers/tts_mcp_client.py --helper "<앱>/Contents/Helpers/CodebasicAgentMCP" status
Helpers/tts_mcp_client.py --helper "<앱>/Contents/Helpers/CodebasicAgentMCP" send --key lesson-1 --display-file summary.txt
```

## 로컬 에이전트 프리뷰

`./build.sh preview`는 안정적인 로컬 서명으로 `build/preview/Codebasic TTS Preview.app`을 만듭니다. 빌드 명령은 앱을 실행하거나 설치하지 않습니다.

프리뷰는 에이전트 작업 공간에서 대본 수신과 편집을 확인하는 용도입니다. 별도 앱 ID와 도우미 ID, `~/Library/Application Support/Codebasic TTS Preview` 및 `/private/tmp/codebasic-tts-preview-mcp-<uid>`를 사용합니다. 프리뷰에 포함된 MCP 도우미를 사용하세요. 프리뷰에서는 시스템 서비스, 전역 단축키, 기존 MCP 음성·지시 메뉴, 계정 로그인 및 음성 합성을 끕니다.

제품과 프리뷰 모두 앱·도우미의 빌드 타깃과 `LSMinimumSystemVersion`이 macOS 14.0입니다(`build.sh`의 `MIN_OS`). 소스가 macOS 14의 SwiftUI `onChange(of:initial:_:)`를 쓰므로 13은 지원하지 않습니다.

## 연결 로그로 확인

앱은 연결 판단마다 `agent` 카테고리에 `[AGENT-CONN]` 한 줄을 남깁니다. 대본·지시·키는 기록하지 않습니다.

```sh
/usr/bin/log show --last 1h --style compact --predicate 'subsystem == "com.seongjoo.SelectedTextTTS" AND category == "agent"'
```

- `connect host=<앱 식별자|unverified> key=<키 ID 앞 12자> lookup=<trusted|unknown|revoked|host_changed> result=<상태>`: 재연결 때 앱을 알아봤는지와 결과. 승인한 앱이 재시작 후 `lookup=trusted result=ready`(또는 `receiving_only`)이면 재승인 없이 연결된 것입니다.
- `approve host=… client=… scope=<persistent|this_run> result=ok|store_failed`: 승인. `this_run`은 앱을 식별할 수 없어 이번 실행에만 허용한 경우입니다.
- `revoke host=… client=… result=ok|unsaved`: 승인 철회.

## 합성 데이터로 확인

`TTS_REQUIRE_STABLE_SIGNING=1 ./build.sh build`는 앱과 도우미의 안정적인 서명과 강화 런타임을 확인합니다. `./build.sh test`는 저장 충돌과 소켓 재시작을 포함한 단위 테스트를 실행합니다.

`python3 Tests/Fixtures/run_agent_app_connections.py`는 직접 실행하는 서명된 테스트 호스트 두 개, 동일한 서명 도우미의 stdio MCP, 실제 수신 제어기와 SQLite 저장소를 사용합니다. 합성 대본과 시험 전용 키 저장소를 사용합니다. 실제 에이전트 앱의 호스트 등록, 운영 키체인과 앱 UI는 별도 검증이 필요합니다. 이전 단일 연결 후보용 수동 하네스는 새 승인 흐름의 통과 기준에 포함하지 않습니다.
