# 외부 에이전트 대본 받기

앱의 **에이전트** 탭에서 기본 지시 또는 여러 사용자 지시를 선택합니다. **새 지시…**에서 이름과 본문을 로컬에 저장합니다. 저장한 지시는 이름으로 찾을 수 있고, 본문 전체를 확인하거나 복사할 수 있습니다. 연결을 허용한 세션에 직접 고른 저장본을 공유합니다.

**공유 지시 선택**에는 현재 공유 대상으로 고른 지시가 표시됩니다. 새 지시를 저장하면 편집기에 열리며, 공유하려면 목록에서 직접 선택하세요. 검색하거나 목록을 열기만 해서는 공유되지 않습니다. **저장**하기 전의 변경은 외부에 공유되지 않으며, 다른 지시를 보고 돌아와도 유지됩니다. **되돌리기**는 마지막 저장본을 다시 표시합니다. 저장한 새 버전을 공유하려면 해당 지시를 다시 선택하세요. 기본 지시의 에이전트용 수정은 앱 내 직접 생성이나 호환용 MCP 지시에 영향을 주지 않습니다.

## 서명된 로컬 도우미 (선택)

도우미 없이도 대본을 붙여넣고 편집할 수 있습니다. 지시를 선택한 경우, 연결된 도우미가 **실제로 조회한 지시의 정확한 버전**을 증명해야 대본을 받을 수 있습니다.

1. 앱에 포함된 **CodebasicAgentMCP**를 stdio 실행 명령으로 등록합니다. 보낼 데이터는 텍스트이며, 호스트 명령 외에 인자·환경 변수·별도 인증 정보가 필요하지 않습니다.
2. **에이전트 연결 → 연결 켜기**를 누르면 대본 받기가 켜지고, 그 뒤 최대 90초 안에 처음 연결하는 에이전트 한 곳을 기억합니다. 기억한 에이전트는 받기가 켜져 있는 동안 다시 묻지 않고 연결됩니다. 에이전트나 앱을 껐다 켜도, 10분 넘게 쉬어도 마찬가지입니다. **받기 끄기**는 수신과 지시 공유를 지금 멈추고, 다시 켤 때까지 앱을 재시작해도 꺼진 상태로 둡니다. 기억은 남으므로 다시 켤 때 새로 허용할 필요는 없습니다. 기억한 에이전트를 기다리는 중에 다른 에이전트를 연결하려면 **새 에이전트 허용**을 누릅니다. 자세한 규칙은 아래 ‘연결 유지’를 보세요.
3. 오른쪽 **지시문**은 기본으로 닫히며 기본 선택은 **사용 안 함**입니다. 지시 선택 없이 일반 대본을 바로 보낼 수 있습니다. 지시를 고르면 정확한 저장본만 읽을 수 있고, 해당 버전 읽기 증명이 있는 대본만 받을 수 있습니다. 저장본을 편집한 뒤에는 새 버전을 고르거나 **사용 안 함**을 선택하세요. 선택한 지시를 삭제하면 **사용 안 함**으로 돌아가며, 이미 읽은 버전에 연결한 제출은 거절됩니다. 증명은 받은 버전과 도우미 일치를 보장합니다.
4. 새로 받은 대본은 편집기에 즉시 열립니다. 이미 열린 대본은 수정 여부에 관계없이 탭에 남습니다. 수정했을 때만 보이는 **받은 원문으로 되돌리기**로 해당 문서의 받은 버전을 복원할 수 있습니다. 재생은 사용자가 직접 눌러야 시작됩니다.

```toml
[mcp_servers.codebasic_tts_agent]
command = "/absolute/path/to/Codebasic TTS.app/Contents/Helpers/CodebasicAgentMCP"
```

앱의 **MCP 설정 복사** 메뉴로 현재 번들 경로가 포함된 Codex 설정이나 Claude Code 사용자 범위 등록 명령을 복사할 수 있습니다. 복사만으로 설정 파일을 바꾸거나 명령을 실행하지 않습니다. 다른 stdio MCP 클라이언트에도 같은 절대 경로를 실행 명령으로 지정하면 됩니다. 앱을 옮기거나 이름을 바꾸면 이 명령 경로만 수정하세요. 전역 에이전트 설정은 앱이 변경하지 않습니다.

- `tts_agent_status`: 앱 연결과 두 권한의 상태를 확인합니다. 지시나 대본은 읽지 않습니다.
- `submit_tts_draft`: 지시를 선택하지 않은 상태에서 `display_text`, 선택적인 `speech_text`, `idempotency_key`를 보냅니다. 지시 선택이 활성 또는 만료·변경 대기 중이면 `instruction_required`로 거절되며 자동으로 우회하지 않습니다.
- `get_tts_instructions`: 인자 없이 호출하면 앱이 승인한 선택을 읽습니다. 정확한 `profile` ID를 지정하는 기존 호출도 지원합니다. 기존 기본 ID는 `explain`, `continue`, `normalize`입니다. 답변의 `revision`과 `body_sha256`은 정확한 버전과 UTF-8 원문을 식별합니다. 수신 증명은 도우미 내부에서만 관리됩니다.
- `submit_explanation_draft`: 읽은 `profile`과 `revision`, `display_text`, 선택적인 `speech_text`, `idempotency_key`를 보냅니다. 두 제출 도구 모두 같은 도우미 세션에서 같은 키와 내용으로 재시도하면 한 번만 열립니다. 같은 키를 다른 내용에 쓰면 거절되며, 같은 내용으로 새 문서를 열려면 새 키를 쓰세요. 접수된 대본의 재생은 사용자가 시작합니다.
- 호환용 기존 기본 지시 조회와 `speak_text`는 각각 그대로입니다. 증명 없는 이전 `mcp_tts_draft.py`는 자동 수신하지 않으며 붙여넣기를 안내합니다. 각 권한은 별개입니다.
- 지시·화면 글·음성 대본은 각각 UTF-8 8 KiB(8192바이트)이고, 한 요청 프레임은 100 KiB입니다. 한도를 넘는 글은 자르지 않고 `too_large`로 거절하며 응답에 넘은 필드와 바이트 수를 담습니다. `tts_agent_status`의 `limits`에서 두 한도를 읽을 수 있습니다. 열린 문서는 최대 6개입니다. 탭이 가득 차면 새 수신은 `busy`로 거절되며, 탭을 닫은 뒤 같은 키로 다시 보낼 수 있습니다. 열어 둔 글의 합계가 UTF-8 256 KiB를 넘으면 `editor_full`로 거절되며, 이때는 글을 줄이거나 옮긴 뒤 같은 키로 다시 보냅니다. 모든 거절 응답은 `structuredContent.status`에 사유 코드를 담고, 앱의 연결 영역에도 사유가 표시됩니다. 새 대본은 분당 6개, 시간당 60개까지 받습니다. 두 한도 모두 시간이 지나면 풀리며, 받기를 직접 껐다 켜면 새로 셉니다. 에이전트마다 최근 전송 키 128개를 기억해 중복을 걸러 냅니다. 이 기억은 에이전트를 다시 실행해도 남지만 앱을 다시 실행하면 사라집니다. 기존의 한도 초과 원문은 자르지 않으며 공유되지 않습니다.
- 열린 대본, 수신 증명, 도우미 승인 기록은 앱을 종료하면 사라집니다. 재생 후에는 기존 설정에 따라 음성 캐시·기록에 남을 수 있습니다.
- 앱이 비정상 종료되면 앱 재시작 및 다음 승인 시 이 버전이 만든 것으로 확인되고 더 이상 연결되지 않는 소켓에 한해 자동으로 복구합니다. “기존 소켓의 출처를 확인할 수 없어 그대로 두었습니다”가 보이면, 이전 **Codebasic TTS** 앱을 종료하고 새 앱에서 같은 동작을 다시 시도하세요. 계속 막히면 복사·붙여넣기를 사용하세요. 관리자가 정확한 경로가 종료된 이전 앱의 소켓임을 별도로 확인한 경우에만 그 항목을 다른 곳으로 옮길 수 있습니다. 경로 전체나 출처를 모르는 파일은 삭제하지 마세요.

## 연결 유지

한 번 허용한 에이전트는 다시 허용하지 않아도 됩니다. 기준은 다음과 같습니다.

- **무엇을 기억하나**: 도우미가 에이전트별로 만든 서명 키의 공개키, 에이전트 이름, 도우미를 실행한 프로그램입니다. 앱 데이터 폴더의 `agent-clients.json`(0600)에 둡니다. 개인키는 로그인 키체인에 내보낼 수 없는 키로 저장되고, 그 키를 만든 도우미만 확인 창 없이 쓸 수 있습니다. 대본이나 지시 내용은 저장하지 않습니다.
- **에이전트 구분**: MCP 클라이언트가 초기화 때 밝힌 이름별로 키가 따로 있습니다. 설정의 실행 인자에 `--client <이름>`을 주면 그 이름을 씁니다. 같은 계정, 같은 도우미라도 키가 다르면 다른 에이전트입니다.
- **다시 연결할 때**: 도우미가 앱이 낸 일회용 값에 서명해 같은 키를 가졌음을 증명합니다. 기존의 서명·프로세스 확인도 그대로 합니다. 받기가 켜져 있고 화면이 잠겨 있지 않으면 바로 연결됩니다.
- **다시 허용해야 하는 경우**: 키가 없거나 바뀐 경우, 도우미를 실행한 프로그램이 달라진 경우, 30일 동안 연결이 없던 경우, 앱을 업데이트해 도우미가 바뀐 경우입니다. 마지막 경우에는 예전 키를 쓸 수 없어 새 키로 한 번 더 허용합니다.
- **화면 잠금**: 잠긴 동안에는 받지 않고 `locked`로 답합니다. 잠금을 풀면 기억한 에이전트가 다음 요청 때 스스로 다시 증명하고 이어집니다.
- **잊기**: 연결 영역의 **기억한 에이전트** 목록에서 **잊기**를 누르면 그 에이전트를 지금 끊고, 진행 중이던 요청과 예전 키를 거절합니다. 다시 쓰려면 새로 허용해야 합니다. 에이전트 쪽에서 키를 버리려면 `CodebasicAgentMCP --client <이름> --forget-key`를 실행합니다.
- **지시 공유는 별개**: 연결이 유지돼도 지시를 읽을 권한이 생기지 않습니다. 고른 지시는 저장된 그 버전만, 고른 그 에이전트에게만 공유합니다. 같은 에이전트가 다시 실행되면 같은 버전을 다시 읽을 수 있고, 지시를 고치거나 지우거나 선택을 풀면 끝납니다. 앱을 다시 실행하면 선택은 남지 않습니다. 한 번 읽은 증명은 10분 뒤 만료되지만, 같은 버전이 그대로 공유 중이면 도우미가 다시 읽어 갱신합니다.
- **기억할 수 없는 경우**: 키체인을 쓸 수 없으면 그 실행 동안만 연결되고, 다음 실행 때 다시 허용해야 합니다.
- **남는 한계**: 같은 계정의 다른 프로그램이 같은 프로그램을 거쳐 같은 이름으로 도우미를 실행하면 구분하지 못합니다. 승인 뒤 중복 방지는 앱을 다시 실행하면 이어지지 않습니다.

## 긴 대본 보내기

터미널(PTY)을 거쳐 도우미에 쓰면 긴 줄이 잘리고 응답이 오지 않습니다. 파이프로 연결하고, 요청 하나를 UTF-8 JSON 한 줄로 끝까지 써야 합니다. `Helpers/tts_mcp_client.py`가 그렇게 보내며, 보낸 결과를 셋 중 하나로 알려 줍니다.

- `confirmed`: 앱이 이 요청에 `accepted` 또는 `duplicate`로 답했습니다.
- `rejected`: 앱·도우미·클라이언트가 거절했고 문서는 열리지 않았습니다.
- `unconfirmed`: 맞는 응답이 오지 않았습니다. 받았는지 알 수 없습니다.

`unconfirmed`는 자동으로 다시 보내지 않습니다. 같은 연결에서 같은 키와 같은 글, 새 요청 ID로 한 번만 다시 보내면 이미 받은 경우 `duplicate`가 옵니다. 출력에는 상태와 바이트 수만 있고 대본 글은 없습니다.

```sh
Helpers/tts_mcp_client.py --helper "<앱>/Contents/Helpers/CodebasicAgentMCP" status
Helpers/tts_mcp_client.py --helper "<앱>/Contents/Helpers/CodebasicAgentMCP" send --key lesson-1 --display-file summary.txt
```

## 로컬 에이전트 프리뷰

`./build.sh preview`는 안정적인 로컬 서명으로 `build/preview/Codebasic TTS Preview.app`을 만듭니다. 빌드 명령은 앱을 실행하거나 설치하지 않습니다.

프리뷰는 에이전트 작업 공간에서 대본 수신과 편집을 확인하는 용도입니다. 별도 앱 ID와 도우미 ID, `~/Library/Application Support/Codebasic TTS Preview` 및 `/private/tmp/codebasic-tts-preview-mcp-<uid>`를 사용합니다. 프리뷰에 포함된 MCP 도우미를 사용하세요. 프리뷰에서는 시스템 서비스, 전역 단축키, 기존 MCP 음성·지시 메뉴, 계정 로그인 및 음성 합성을 끕니다.

제품과 프리뷰 모두 앱·도우미의 빌드 타깃과 `LSMinimumSystemVersion`이 macOS 14.0입니다(`build.sh`의 `MIN_OS`). 소스가 macOS 14의 SwiftUI `onChange(of:initial:_:)`를 쓰므로 13은 지원하지 않습니다.

## 합성 데이터로 확인

`TTS_REQUIRE_STABLE_SIGNING=1 ./build.sh build`는 앱과 도우미의 안정적인 서명과 강화 런타임을 확인합니다. `./build.sh test`는 둘 이상의 프로세스에서 로컬 저장 충돌과 소켓 재시작을 포함한 테스트를 실행합니다. `Tests/Fixtures/run_local_draft_candidate.py`는 작업트리 `build/` 안에서 서명된 실제 stdio 프로토콜로 자동 연결, 앱 재시작, 기본 차단, 신뢰할 수 없는 프로세스 거절, 실제 조회 증명, 재수신, 편집·되돌리기·삭제 및 취소를 검증합니다. 실제 설치 앱, 저장된 사용자 지시, 음성 제공자 및 재생은 사용하지 않습니다.

`python3 Tests/Fixtures/run_persistent_pairing.py`는 같은 방식으로 연결 유지를 확인합니다. 한 번 허용한 뒤 에이전트와 앱을 정상·비정상 종료했다가 다시 실행하는 경우, 화면 잠금, 다른 키, 다른 실행 프로그램, 키 분실, 잊기, 끊기, 지시 버전 변경, 한도 경계의 긴 대본, 응답 유실 뒤 재시도를 다룹니다. 시험용 키는 로그인 키체인에 일회용 이름으로 만들고 끝나면 지웁니다. `--real-idle plain|linked`는 실제로 600초 넘게 쉰 뒤에도 받는지 확인합니다.

`python3 Tests/Fixtures/run_local_draft_candidate.py --preview`는 합성 제품·프리뷰 리스너를 동시에 띄워 소켓과 서명 ID가 분리되는지 확인합니다. `python3 Tests/Fixtures/run_tts_preview_isolation.py`는 임시 프로필에서 설정, 키 파일, SQLite, 지시 저장소와 계정 연결 차단을 확인합니다.
