# 로컬 MCP 음성 입력 (실험적)

앱에 포커스를 둔 뒤 macOS 상단 **Codebasic TTS** 앱 메뉴에서 **로컬 MCP 음성 입력 허용 (이번 실행)**을 선택해야 합니다. 기본적으로 꺼져 있고, 앱 종료 또는 메뉴에서 끄면 비활성화됩니다. 이 어댑터는 앱을 실행하지 않습니다. 사용 중인 음성과 TTS 백엔드를 그대로 사용합니다. 같은 macOS 로그인 계정의 다른 프로그램도 켜진 동안 요청할 수 있으므로 신뢰하는 프로그램에서만 사용하세요. 요청한 내용은 현재 선택한 백엔드가 클라우드라면 해당 제공자에게 전송될 수 있으며, 앱의 기존 캐시/기록 정책도 적용됩니다.

별도 MCP 클라이언트에 아래 예시를 각 클라이언트가 지정하는 설정 파일에 수동으로 추가합니다. 경로는 이 저장소 위치에 맞게 변경하세요. 이 작업은 사용자 설정을 자동 변경하지 않습니다.

```json
{
  "mcpServers": {
    "codebasic-tts": {
      "command": "/usr/bin/python3",
      "args": ["/absolute/path/to/SelectedTextTTS/scripts/mcp_speech.py"],
      "env": {"CODEBASIC_TTS_SIGNER_SHA1": "TRUSTED_CERT_SHA1_40_HEX"}
    }
  }
}
```

Codex에서의 설정과 설치 없는 재생 확인은 [Mac용 Codex MCP 빠른 확인](mcp-codex-quick-test.md)을 참고하세요.

표준 입출력 줄 단위 MCP 2025-11-25만 구현합니다. `speak_text`의 `text`는 최종 일반 텍스트(공백만 있는 문자열 불가, UTF-8 최대 4096바이트), `idempotency_key`는 요청마다 새로 만드는 영문자·숫자·`._-`의 1~128자입니다. 재시도에는 같은 키와 같은 텍스트를 사용하세요. `accepted`는 접수일 뿐 실제 재생이나 완료를 의미하지 않습니다. `unconfirmed`일 때도 같은 키로 재시도해야 합니다. 동일 키의 다른 텍스트는 거부합니다. 중복 방지는 켜진 세션의 최근 128개 요청에 한정되며 종료·비활성화나 오래된 항목 제거 후에는 보장되지 않습니다.

음성 요청은 LLM 대본 생성·해설이나 수식 토큰 제거를 거치지 않습니다. 기존 음성 합성 엔진의 문단 분할 과정에서 공백과 줄바꿈은 정리될 수 있습니다. 사용자가 수동 재생 중이거나 음성·해설·정규화 처리가 진행 중이면 새 요청은 `busy`로 거절됩니다. 별도의 큐는 없습니다.

두 MCP 도우미는 같은 UID만으로 앱을 신뢰하지 않습니다. 도우미 설정에 독립적으로 확인한 **공개 서명 인증서의 SHA-1 지문**(40개 16진수)을 줘야 합니다. 소켓 연결에서 macOS가 준 상대 audit token으로 실행 중인 앱의 서명을 검증하고, 예상 앱 ID `com.seongjoo.SelectedTextTTS`와 인증서가 모두 맞을 때만 요청을 보냅니다. 지문 없음, 다른 서명 또는 애드혹 서명에서 연결은 실패합니다. 앱 자체의 수동 재생·해설에는 영향이 없습니다. [설정 절차](mcp-codex-quick-test.md#실제-연결의-서명-고정)를 참고하세요.

통신은 `/private/tmp/codebasic-tts-mcp-<uid>/s.sock` 유닉스 소켓만 사용하며 TCP 포트는 열지 않습니다. 디렉터리는 0700, 소켓은 0600이고 양쪽에서 상대 UID를 확인합니다. 비정상 종료로 소켓 경로가 남으면 앱은 기존 경로를 자동 삭제하지 않고 시작을 거부합니다. 앱이 완전히 종료된 것을 확인한 뒤 소유자와 파일 종류를 점검하고 잔여 소켓을 직접 지우세요. 앱이 꺼졌는지 기능이 꺼졌는지는 어댑터가 구분하지 못해 `offline`으로 보고할 수 있습니다.

검증: `./build.sh test` 또는 `./build.sh build`만 사용하세요. 인자 없는 `./build.sh`는 앱을 설치·등록·실행하므로 빌드만 할 때 사용하지 마세요. 테스트는 실제 음성 제공자나 앱을 호출하지 않습니다.

## `as_frame`: 화면의 원문과 음성 대본

앱의 **해설 → 전체 재생**은 화면에 `as_frame 옵션을 켜면 데이터프레임을 반환합니다.`를 남기면서, 정규화에서 받은 `애즈 프레임 옵션을 켜면 데이터프레임을 반환합니다.`를 별도로 합성에 넘길 수 있습니다. 격리 테스트에서 `애즈 프레임`이 합성 입력에 한 번만 들어가고 괄호나 원문 식별자는 포함되지 않았습니다. 정규화 응답과 합성 엔진은 테스트 대역이므로 실제 모델의 표현 판단이나 들리는 발음까지 확인한 것은 아닙니다.

현재 로컬 MCP `speak_text`는 단일 `text`를 합성과 자막 양쪽에 쓰고 정규화를 우회합니다. 에이전트가 `애즈 프레임`을 보내면 자막에도 `애즈 프레임`이 보입니다. `as_frame`을 보내면 합성에 전달되는 것도 `as_frame`입니다. 별도 `display_text`는 아직 받지 않습니다. 두 텍스트를 동시에 다루려면, 기존 호출은 그대로 유지하면서 표시용 문자열을 별도로 받는 확장이 필요합니다.

아래 테스트는 가짜 설정에서 발음 사전의 빈 목록이 저장·재로드 후에도 비어 있고, 키가 없을 때만 기본 항목을 넣으며, 현재 앱이 **이번 실행 힌트 → 발음 사전 → 기본 대본 지시** 순으로 조합하는 것도 확인합니다. 실제 설정이나 음성 제공자에 접근하지 않습니다.

```sh
/usr/bin/python3 -B Tests/Fixtures/run_tts_pronunciation_case.py
```
