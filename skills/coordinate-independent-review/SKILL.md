# 독립 리뷰 조정

## 배정과 보증 등급

주 에이전트는 사용자가 구현을 맡긴 모델이며, 어디서 어떻게 실행되든(사용자 세션, 다른 에이전트가 시작한 세션, CLI 등) 같습니다. 작업 이슈에서 주 에이전트와 그 계열을 확인합니다. 대화 UI만 바뀌면 배정을 유지합니다. 구현 책임자 계열이 바뀌면 다음 시도에서 다시 배정합니다. 가용하면 아래 배정을 사용합니다.

| 주 에이전트 계열 | 가용하면 독립 자문하는 두 계열 |
| --- | --- |
| OpenAI (ChatGPT/Codex) | Anthropic, Google |
| Anthropic (Claude) | OpenAI, Google |
| Google (Antigravity) | OpenAI, Anthropic |

괄호는 하네스 예시입니다. 같은 계열의 다른 독립 세션(상위 모델 포함)은 자문으로 B 등급에 셉니다. 검토 모델과 세션은 모두 어드바이저이며 결정권이 없습니다. 다른 하네스나 계열이 항상 있다고 가정하지 않습니다. 보증 등급은 실제로 모은 유효 자문의 범위를 기록하며 결정 주체를 바꾸지 않습니다.

| 등급 | 조건 |
| --- | --- |
| A · 다계열 | 다른 계열의 유효 독립 자문 보고가 하나 이상 |
| B · 단일 계열 독립 | 같은 계열의 서로 다른 독립 세션에서 받은 유효 자문 보고가 둘 이상 |
| C · 자체 검토 | A·B 조건 미충족(유효 자문이 없거나 같은 계열 하나뿐) |

A와 B는 같은 권한을 가지며 등급은 보증 수준의 기록입니다. 프로젝트 최소 등급은 A>B>C 순서로 비교합니다. 주 에이전트 계열을 확인할 수 없으면 등급을 정하지 않고 사용자와 상의합니다. 마지막 자문 뒤의 HEAD는 그 자문이 낸 지적의 수정만 담고 같은 SHA의 실행 검증을 통과하면 그 자문의 등급을 승계하며, 승계 사실을 기록합니다. C는 아래 자체 검토 절차의 실행 증거를 추가로 요구합니다. 등급, 빠진 자리와 이유(미가용·로그인 만료·미승인)를 이슈와 PR 본문 첫머리에 적습니다. 프로젝트가 승인한 모델·하네스·자료·전송 대상만 사용하고, 미가용이면 미충족으로 기록하며 자동 대체하지 않습니다.

유효 보고는 같은 HEAD·기준 SHA에 대한 독립 첫 자문 보고(또는 아래 증분 조건의 보고)이며 서빙 모델이 실행 출력으로 확인된 것입니다. 어드바이저의 모델·노력 수준이 그 하네스 출력에 보이지 않으면 CLI처럼 그것이 보이는 환경에서 실행합니다. 구현 세션이나 오케스트레이터 안의 서브 에이전트, 모델을 자기 신고했거나 `미확인`으로 적힌 결과, 같은 세션의 중복 보고, 자동 리뷰는 유효 보고가 아닙니다. 독립 세션은 별도 프로세스로 새로 시작하고 구현 문맥과 다른 의견 없이 같은 중립 브리프와 읽기 전용 접근을 가진 세션입니다. 노력 수준이 미지정·미확인이어도 보고는 유효하며 그 값을 기록합니다. 같은 모델 세션의 보고는 동일 모델 표로 표시합니다. 실패·시간 초과·잘린 실행은 `incomplete`이며 지적 없음으로 세지 않습니다.

## 결정 모델

어드바이저는 지적 ID, 심각도, 상황과 영향, 근거 위치, 재현 방법과 권고를 담은 자문 보고만 냅니다. 지적 종결, 검토 대화 닫기, PR 게이트, 통과·실패 판정은 하지 않으며, 보고의 결론은 판정이 아니라 자문 권고로 기록합니다. 어드바이저는 서로 토론하지 않습니다. 이 규칙의 근거는 독립성과 감사 가능성입니다.

결정은 주 에이전트(주 모델)만 하며, 주 에이전트는 구현자이자 결정자입니다. 주 모델은 자문 보고, 지적 ID, 실행·재현 결과를 읽고 지적마다 처리(수정·후속 이관·기각·중단)와 다음 단계(다음 시도·PR 등록·`review` 병합·범위 축소·중단)를 같은 HEAD·기준 SHA에 대해 정합니다. 처리 값은 이 네 가지뿐이며 기여 기록의 채택·보류·기각은 각각 수정·후속 이관·기각에 대응합니다. 결정과 근거, 자문을 어떻게 반영했는지, 주 모델이 무엇이었고 어디서 실행됐는지, 모델과 요청·관찰 노력 수준을 확인 가능한 만큼(확인할 수 없으면 `미확인`) 기록합니다. 기각과 후속 이관에는 근거를 적습니다. 지적을 닫으려면 같은 SHA의 실행 증거와 체크리스트 근거가 있어야 합니다. 오케스트레이터는 증거 정리와 기록만 맡습니다. 사용자는 어떤 결정이든 나중에 뒤집을 수 있습니다.

지적의 사실 여부는 실행·재현이나 구체적인 정적 확인으로 정합니다. 다수 의견은 검증이 아니라 우선순위 신호입니다. 유효 자문 N개 중 ⌊N/2⌋+1 이상이 같은 지적을 냈는지, 동률·소수 의견인지를 주 모델에게 입력으로 주며, 재현되지 않은 지적은 다수가 냈더라도 그 자체로 처리 필수가 아닙니다. 주 모델이 다수 의견과 다르게 정하면 근거를 기록합니다. 근거 없는 이탈은 결정으로 받지 않습니다. 새 근거 없이 이미 해소된 지적을 다시 올린 보고는 무효 자문입니다.

재현되거나 정적으로 확인된 차단 지적은 한 어드바이저만 냈더라도 주 모델이 처리해야 하는 증거입니다. 어드바이저의 거부권이 아니라 증거의 효력이며, 주 모델은 이를 기각하거나 이관할 수 없고 고쳐서 재검증하거나 중단하는 것만 고를 수 있습니다. 이런 지적은 범위 확장으로 분류할 수 없고, 이 지적을 빼는 범위 축소는 사용자와 상의합니다. 넘기려면 사용자와 상의합니다. 주 모델의 결정은 PR 등록 전 게이트, `review` 병합의 증거 충분 조건, 사용자의 기본 브랜치 직접 병합을 바꾸지 않습니다.

## 노력 수준

모든 자문 실행과 주 모델 결정은 노력 수준을 명시합니다(예: Claude CLI `--effort`, Codex reasoning effort, Antigravity thought level). 수준 값의 어휘는 하네스마다 다르며 프로젝트 설정을 따르고, 실행마다 요청 수준과 출력에서 관찰한 수준을 기록하며 관찰할 수 없으면 `미확인`입니다. 지정 없이 기본값으로 돌린 실행은 요청 수준 `미지정`으로 기록합니다. 더 깊은 검토가 필요하면 남은 기회 안에서 수준을 올립니다. 수준을 올려도 자문·시도 상한은 늘어나지 않습니다.

## 검토 절차

1. [브리프](references/review-brief.md)에 이슈 목표, 고정한 범위와 완료 조건, 정확한 HEAD·기준 SHA, 읽기 전용 소스·diff·허용 자료, 노력 수준과 자문 보고 형식을 고정합니다. 각 어드바이저에게 같은 중립 브리프를 보내고 첫 보고가 확정될 때까지 구현자의 결론이나 다른 의견을 공유하지 않습니다. 비밀·운영 자료는 제외합니다. 5관점(소프트웨어 공학·UI/UX·최종 사용자·방어적 보안·배포)은 검토 범위이며 별도 2축 프리셋은 자체 정의를 따릅니다.
2. 첫 시도, 기준 SHA 변경, 이력이 이어지지 않거나 불명확한 경우, 구현 책임자 계열 변경에는 전체 diff를 검토합니다. 그 밖의 2번째 시도부터는 같은 역할로 이전 범위를 직접 확인한 같은 어드바이저에게만 직전 HEAD 대비 diff, 자신의 이전 보고와 그 지적의 처리 결과를 주어 증분 재검토를 받고, 새 어드바이저나 바뀐 역할에는 전체 diff를 줍니다. HEAD·기준 SHA가 바뀌면 기존 근거는 원래 조합에 귀속합니다.
3. 실행 검증은 승인된 격리 환경의 같은 HEAD·기준 SHA에서 합성 자료로 합니다. 실제 자료나 환경에는 별도 승인이 필요합니다. [증거 양식](references/evidence.md)에 실행 환경·절차·결과와 정적 판단·미확인을 구분해 기록합니다.
4. 수정 뒤 새로 생긴 지적은 직전 수정이 깨뜨린 회귀(이번에 처리)와 범위 밖 요구나 새 경계 사례인 범위 확장(후속 이슈)으로 주 모델이 나누어 기록합니다. 재현된 차단 지적은 범위 확장으로 분류하지 않습니다.

자체 검토(C 등급, 그리고 모든 등급의 마지막 점검)는 고정 체크리스트를 씁니다. 체크리스트는 완료 조건, 5관점, 회귀, 비밀·운영 자료 제외, 실행 검증입니다. 같은 SHA에서 테스트·검사·재현 스크립트 중 하나 이상이 통과해야 하며 다시 읽기만으로는 종료하지 않습니다. 반박 관점의 재검토는 가능하면 새 문맥의 별도 실행으로 합니다.

## 시도 상한과 종료

자문 1회는 하나의 HEAD·기준 SHA 조합에 같은 중립 브리프를 보내 그 시점에 가용한 어드바이저들의 보고를 받는 한 묶음입니다. 첫 보고 묶음과 증분 재검토 묶음을 모두 1회로 셉니다. 시도 1회는 주 모델의 결정 한 번이며, 같은 HEAD에서 다시 내린 결정도 셉니다. 재실행은 직전에 센 같은 HEAD·기준 SHA 조합에서 어드바이저 미가용이나 `incomplete` 때문에 다시 받는 자문만 뜻하며, 시도나 자문으로 세지 않고 조합마다 최대 2회입니다. 그 뒤에는 사용자와 상의합니다. 기록 수정은 세지 않습니다. 수준을 올려 같은 조합에서 다시 받는 자문은 자문 1회로 셉니다.

한 PR이나 작업 후보의 자문은 최대 3회, 시도는 최대 5회입니다. 시도 1~3은 자문 1회, 주 모델 결정, 필요한 수정과 실행 검증 순서입니다. C 등급에서는 시도 1~3의 자문 자리를 체크리스트 자체 검토가 대신하며 같은 상한을 적용합니다. 시도 4~5에는 새 자문 없이 주 모델이 남은 지적을 결정하고, 수정은 같은 SHA의 실행 검증과 자체 점검 체크리스트로만 확인합니다. 증거 충분 조건을 충족하면 그 시점에 끝냅니다. 5회 뒤에도 해결되지 않으면 작업을 멈추고 선택지와 권고안을 붙여 사용자와 상의하며, 사용자 결정 없이는 더 진행하지 않습니다. 상한 도달은 품질 통과가 아닙니다. 재현된 차단 지적 수가 두 시도 연속 엄격히 줄지 않으면(직전 세 시도에서 c₃ ≥ c₂ ≥ c₁이고 c₃ > 0) 상한 전이라도 주 모델이 범위 축소나 중단을 정하거나 사용자와 상의합니다. 상한은 프로젝트가 낮출 수 있고, 높이거나 카운터를 초기화하는 것은 사용자만 합니다.

불확실성이 남은 채 결정한 항목(후속 이관·보류, 재현이나 관찰이 미확인인 상태의 결정)은 결정을 유지하되 이슈에 결정, 남은 불확실성, 결정을 다시 볼 증거 조건과 기록할 이슈를 남깁니다. 이후 그 항목에 관한 증거(실행 결과, 재현, 관찰 모델·노력 수준 확인 등)가 모이면 해당 이슈에 덧붙여 기록합니다(예: #6에서 이관한 항목은 #7). 새 증거가 증거 조건을 충족하면 수정이 필요한지는 주 모델이 직접 판단합니다. 필요하다고 판단하면 사용자 승인을 기다리지 않고 결정 근거를 이슈에 남긴 뒤 새 작업 후보로 구현하고 PR을 엽니다. 그 PR은 자체 자문 3회·시도 5회 상한을 새로 가지며, 이미 끝난 PR의 상한을 늘리지 않습니다. 한 이관 항목에서 시작한 후속 PR은 최대 3개이며, 그 뒤에는 사용자와 상의합니다. 상한에서 멈춘 작업과 같은 범위는 새 후보로 다시 열지 않습니다. 변경이 `review`에 병합되면 증거, 결정과 근거, PR 링크를 붙여 사용자에게 검토를 요청합니다. 조건을 충족하지 않는 증거는 기록만 하며 새 자문이나 시도를 시작하지 않습니다.

단계마다 다음 행동 주체를 한 명만 이슈에 적고 기한을 둡니다. 서로를 기다리는 순환 대기를 금지합니다. 에이전트가 기한을 넘기면 주 모델이 결정하지만, 사용자를 기다리는 중에는 기한이 지나도 다시 알리고 계속 기다립니다. 주 모델이 결정할 수 없게 되었을 때, 재시도 상한 뒤에도 실행이 `incomplete`일 때, 재현된 차단 지적을 고칠 수 없을 때, 주 모델이 판단 불가라고 답할 때는 사용자와 상의합니다. 상의하는 동안 다음 행동 주체를 사용자로 기록하고 시도를 멈춥니다. 세션 사이 메시지는 결과·차단·질문만 보냅니다.

## PR 등록과 `review` 병합

PR 등록 준비도는 주 모델이 `pass`, `blocked`, `unverified`로 결정하고 기록합니다. 프로젝트 최소 등급 충족(C는 자문 없이 체크리스트와 실행 증거), 같은 SHA의 통과한 실행 검증, 주 모델 결정과 차단 지적 처리가 이슈에 기록되고 등록 권한이 있으면 `pass`입니다. 실행 실패, 재현된 미해결 차단 지적, 결정 불가는 `blocked`, 필수 증거 누락은 `unverified`입니다. PR은 초안을 포함해 같은 후보 HEAD·대상 브랜치 기준 SHA의 근거를 이슈에 기록하고 준비도가 `pass`인 다음에 엽니다. 차단 또는 미확인 상태에서는 이슈에 원인과 필요한 근거를 남깁니다.

증거 충분 조건은 고정된 HEAD·기준 SHA와 범위, 체크리스트 통과, 같은 SHA의 실행 검증 통과, 재현되는 차단 지적과 회귀 없음, 주 모델 결정과 근거의 기록입니다. 이 조건을 충족하고 프로젝트 최소 등급 이상이면 구현 에이전트가 PR을 `review`에 병합하고 닫을 수 있습니다. 병합 직전에 HEAD·기준 SHA가 증거와 같은지 다시 확인하고 다르면 병합하지 않습니다. 사용자와 상의 중이면 병합하지 않습니다. 병합 SHA, 등급, 증거 링크와 병합 주체를 이슈에 남깁니다. 범위 밖이거나 대체 PR이 있으면 이유와 후속 이슈를 기록하고 병합 없이 닫습니다. 기본 브랜치 승격은 등급과 무관하게 사용자가 직접 병합하며, 승격 PR에는 포함된 변경의 등급을 요약합니다.

## 기여 기록

회차마다 [증거 양식](references/evidence.md)의 기여 기록을 남기고, 승격 후보를 제시할 때 이슈의 모든 회차를 집계합니다. 집계 키는 관찰된 계열·하네스·모델, 하네스 출처(관찰 또는 커밋 트레일러의 신고)와 역할이며, 신고값과 관찰값은 한 행으로 합치지 않습니다. 계열은 공백·대소문자를 무시해 세 계열 이름에 맞추고, 비어 있거나 미확인이거나 그 밖의 표기는 미확인으로 집계합니다. 트레일러가 없거나 역할을 알 수 없는 커밋은 미확인 행으로 남기며 요청 모델로 채우지 않습니다. 자문 기록은 지적을 제기하고, 지적의 처리(채택·보류·기각·미처리)와 해소는 관찰된 하네스의 판단 기록(트레일러 역할 `integration`, 주 모델 결정)만 정하며, 신고되었거나 출처가 기록되지 않은 하네스의 판단 기록은 상태를 바꾸지 않습니다. 지적 ID는 이슈에서 한 번 세고 지금까지 보고된 가장 높은 심각도를 씁니다. 처음 제기된 회차에 함께 제기한 행은 모두 제기로, 이후 다른 행의 보고는 확인으로 셉니다. 처리는 가장 늦은 회차의 판단을 쓰고 엇갈리면 미처리, 보류, 채택, 기각 순으로 앞선 값을 씁니다. 차단 지적은 그 회차의 모든 판단이 채택이면서 해소일 때만 해소로 세고(미처리·보류에 붙은 해소 표시는 무시), 마지막 판단 뒤의 회차에서 다시 보고되면 새 판단 전까지 미해소로 되돌리며, 기각된 차단 지적도 미해소에 남긴 채 따로 표시합니다. 이 미해소는 기여 집계의 상태이며 PR 등록을 막는 미해결 차단 지적인지는 PR 등록 준비도에서 주 모델이 결정합니다. 실행은 HEAD·기준 SHA와 실행 ID로 한 번 세고 결과가 엇갈리면 실패·미확인·통과 순으로 나쁜 쪽을 쓰며, 미확인을 실패로 세지 않습니다. 기각·심각도 하향의 근거 요건과 배정표 대조 같은 집계 정책 검증은 [#7](https://github.com/codebasic/multi-agent-dev/issues/7)에서 정합니다. 기여 기록은 사실 기록이며 필수 검토·실행 증거나 준비도 판단을 대체하지 않고, 수치만으로 에이전트나 모델의 우열을 정하지 않습니다.
